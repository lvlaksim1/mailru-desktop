# Текущие ограничения — MailRu Desktop, 2026-10-09

Три пользовательские проблемы просмотра v0.3.32 закрыты сообщением владельца.

1. Событийная доставка новых писем Windows: для телефона без RuStore/VK APK предусматривает GCM/FCM и HMS; точный выбор на телефоне не установлен. Возможность FCM из независимого настольного процесса подтверждается исходниками и опытом Superhuman 2026, но выпуск токена, который примет почтовый сервер Mail.ru, и фактическая доставка не доказаны. Исследование Google-транспорта APK запущено Actions 37872182332, итог требует проверки.
2. Точный договор регистрации PushMeApiImpl в крупных методах декомпилирован неполно; нельзя объявлять серверный путь подтверждённым живым вызовом.
3. Issue #77 — немедленная отправка уже отложенного письма заблокирована из-за отсутствия атомарной защиты от двойной доставки.
4. Другие независимые долги: реальная доставка по расписанию, подтверждение прочтения, альтернативный поиск. Секреты и содержание писем не сохранять в Git; уже принятые функции не менять.


Уточнение 2026-10-09: исследование источника Google FCM в APK успешно завершено. Главный открытый вопрос — получение независимого действительного FCM-токена для Windows, принятие его Mail.ru PushMe и фактическая доставка уведомления. Google Play Services в Android — внешняя системная служба, а не самостоятельный сетевой получатель внутри APK. Автоматический частый опрос писем не соответствует требуемой событийной доставке.


Открытая техническая проверка 2026-10-09: при исходных идентификаторах push_sender_id=1098335887158 и gcm_defaultSenderId=61247752867 независимая регистрация Windows ещё не доказана; уточняется FirebaseInfoProvider через Actions 37874791066. Принятие его токена Mail.ru PushMe и фактическое event=4 также не проверены. Нельзя передавать/копировать существующий телефонный токен и нельзя объявлять успех по одной декомпиляции APK.


Коррекция после испытаний 2026-10-09: блокировка самого получения токена без Android снята только для одноразового GCM register3 (TOKEN_ISSUED, Actions 37875870944/37876061718), подтверждён защищённый MCS LOGIN_OK. Остались отдельные недоказанные условия: равенство этого токена исходному Android FirebaseInstanceId, долговременная доставка и переподключение; принятие регистрации Mail.ru PushMe и живое событие event=4 для собственного тестового аккаунта. Попыток отправки почтовых OAuth в GitHub не было и не допускается. В работе восстановление точных настроек подписки Actions 37876287988.


09.10.2026: Google GCM token и MCS LOGIN_OK изолированного получателя проверены, переносимый Windows стенд и локальный DPAPI проверены. Фактический blocker — точные исходные параметры capabilities/client в PushMeSDK и доказательство принятия локального OAuth аккаунта Mail.ru. В тестовом макете capabilities={} пока не является подтверждённой конфигурацией официального APK и может исключать нужные события. Сохранение исходных классов из повторного JADX Actions 37877449399 ещё не завершено. Пользовательские почтовые токены не запускать в CI, нет E2E подтверждения event=4. CI основного продукта 37877585319 имел первоначальное падение WPF smoke, повтор завершился SUCCESS без изменений продукта; первопричина не выяснена.


09.10.2026 после исправления: больше нет неопределённости о can_mail: точный MailCapabilitiesProvider из APK извлечён и испытательная программа обновлена. Actions 37878519042 и 37878867912 SUCCESS, Windows EXE 37878867920 PASS. Остаётся блокировка на уровне фактической интеграции серверов: нет проверенного успешного PushMe validate_result для независимо полученного Windows Google токена и нет реального события event=4. Настоящая проверка требует сохранённого локального мобильного OAuth уже авторизованного пользователя; данные запрещено отправлять в GitHub, пользовательский ПК в этом разговоре не подключён. Клиентская Android hardware metadata Windows стенда синтетическая и сама по себе не удостоверяет Android-экземпляр; серверное принятие проверять отдельно. Нельзя объявлять полную готовность к релизу.


09.10.2026: прежняя блокировка ручным Python экспериментом снята — native .NET8 исследовательский режим интегрирован в v0.3.33 main. Остаются: 1) финальная CI и подтверждение обоих установщиков v0.3.33; 2) реальная Mail.ru PushMe подписка выбранного аккаунта под локальным OAuth (на CI недоступна и не должна выполняться); 3) подтверждённое получение event=4 и независимость телефона. Синтетические поля Android-устройства не доказывают идентичность настоящего телефона. Функция не запускается автоматически и не обещает долговременной надёжности до E2E. Не объявлять успешную доставку из одной компиляции.


После 09.10.2026: сборка и установщики v0.3.33 больше не заблокированы — CI 37880498382 PASS, release 37880613099 PASS. Единственная ключевая недоказанная часть получения новых писем — реальный PushMe сервер принимает ли независимый Windows FCM token, и будет ли на нативном канале MCS event4. Для этого нужен испытательный подключённый ящик в окне самого MailRu Desktop на ПК владельца, никаких логинов или токенов через GitHub/чат. Не утверждать что события уже работают. Также долговременное переподключение и дубли будут прорабатываться после успешного события.


09.10.2026 after v0.3.34 release: initial AltProd TLS issue addressed by official Prod verified TLS and empty POST HTTP200. Still need live ACCOUNT_ACCEPTED of selected saved user account and genuine event4 on Google MCS in the newly integrated app; user test needed. Remote GitHub TLS results do not independently prove failure cause on user's network. No reason to request mailbox credentials, all auth remains in local DPAPI. Cleanup of trial token must be inspected after the next run. Long-running reliability and all-account delivery deferred until E2E success.

## 09.10.2026 — открытый риск после выпуска v0.3.36

Не осталось блокировки сборки: все CI шаги и оба инсталлятора SUCCESS. Не доказаны в пользовательской Windows-среде: подписка сразу нескольких реальных ящиков на общий токен; восстановление событий после длительного разрыва/выхода и повторного входа; отсутствие дублей; непрерывное получение на оставшихся аккаунтах после удаления одного. Снятие одного аккаунта пока реализовано консервативно через отзыв всего старого общего токена и повторную регистрацию остальных; если сервер не подтвердит отзыв, новый канал не запускается и требуется повторная попытка. Не повышать уровень доказательства без локального опыта, секреты не выгружать в GitHub.

## 09.10.2026 — оставшиеся ограничения после source-first фикса v0.3.37

Отчёт владельца 0/32: известна одна установленная несовместимость обработки PushMe `validate_result`, устранена в коде; исходная причина фактического обрыва из прежнего журнала не восстанавливается из-за обобщённого статуса, не выдавать догадку за доказательство. Не восстановлены до конца корутинные методы нового SDK `SubscriptionUseCase.invoke`, `UnsubscribeUseCase.invoke`, `PushMeApiImpl.setSettingsInternal/unsubscribeByDeviceId`. Отсутствует исходная реализация системного Google MCS внутри APK Mail.ru (ею занимается Google Play services). Адресная отписка отдельных аккаунтов ещё не воспроизведена; в Windows остаётся осторожная смена общего токена, не идентичная исходному поведению SDK. Полная серверная доставка 32 аккаунтов не подтверждена. Владелец запретил новые сетевые эксперименты для подбора поведения.

# Episode — 2026-10-07 — v0.3.0 to v0.3.4 UI and parser cycle

## Context

The project moved from the v0.2.0 feature-bundle UI to a substantially redesigned desktop mail client driven by Owner feedback from real daily use.

Major modern-UI rebuild:
- dark theme became the first-run default;
- tabs were replaced by persistent navigation plus message list and preview;
- right-side multi-account rail was introduced;
- account unread badges were implemented;
- startup loading was hardened;
- stored `refresh_token` began to be used for automatic `access_token` renewal through `POST https://o2.mail.ru/token`, `client_id=mail-android`.

Controlled live validation confirmed the refresh-token exchange and subsequent Inbox loading.

## Multi-account regression discovered after v0.3.3

Owner added a second account. Result:
- folders loaded;
- folder unread counters loaded;
- Inbox displayed no recognized messages.

Owner supplied the raw server response. The response is valid and contains messages. Important observed form:

`body.folders_content[].threads[].representations[]`

A representation contains fields such as:
- `flags.unread`, `flags.flagged`, `flags.pinned`, `flags.attach`;
- `attachments_count`;
- `subject`;
- `date`;
- `folder`;
- `snippet`;
- `correspondents.from/to/cc/bcc`;
- `message_id_last`.

Inbox metadata in the supplied response includes `messages_total=319` and `messages_unread=11`.

### Root cause

`MailRuThreadStatusParser` in v0.3.3 recognized:
- `thread.base_message`;
- `thread.messages[]`;
- direct thread-like objects with subject/snippet.

It did not recognize `thread.representations[]`. Therefore folder parsing worked, while message parsing returned zero rows.

## Stable Owner directives reinforced in this episode

- Many accounts are expected; switching must be fast and visible.
- Account badge means Inbox unread messages specifically.
- Dark theme is mandatory and default.
- Prefer compact desktop information density over mobile-card layouts.
- Preview pane should contain the actual working message functionality, not duplicate it in a separate window.
- Research/test repeated network requests must be spaced by at least five seconds; do not put that fixed delay into ordinary runtime.
- Keep release/update delivery as installers; user expects update-installer links.

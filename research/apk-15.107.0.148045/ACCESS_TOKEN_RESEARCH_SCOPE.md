# Текущая граница исследования Mail.ru Desktop

Дата изменения постановки: 2026-10-06.

## Главный критерий

Домен сервера больше не является ограничением.

В область исследования входят все механизмы официального приложения Mail.ru, которые способны работать с тем же почтовым OAuth-токеном:

`ru.mail.oauth2.access`

и используют именно это значение для авторизации запроса. Способ передачи зависит от узла: обычный почтовый API использует `access_token`, новый поиск — параметр `t`, подсистема звонков — `Authorization: Bearer <token>`.

Узел может быть `aj-https.mail.ru`, `go.mail.ru` или любым другим.

## Что входит

Команда входит в область исследования, если код официального клиента подтверждает один из вариантов:

1. тип авторизации `TORNADO`;
2. тип `TORNADO_MPOP`, но команда поддерживает OAuth-переключение через `ServerCommandBase.getApiType()`;
3. другой сетевой механизм, который явно получает именно `ru.mail.oauth2.access` и передаёт это значение серверу как авторизационные данные, независимо от имени параметра или заголовка.

## Что пока не входит

Не исследуем как рабочий API Mail.ru Desktop механизмы, для которых требуется независимая авторизация:

- отдельный Mpop-токен вместо OAuth `access_token`;
- отдельный токен Облака, Календаря, VK или другой службы;
- веб-cookie как обязательный способ авторизации;
- IMAP/SMTP и специальные пароли приложений;
- анонимные/служебные API, не связанные с нашим почтовым `access_token`.

Наличие строки `access_token` само по себе недостаточно: необходимо доказать, что используется именно тот же токен `ru.mail.oauth2.access`.

## Подтверждённая механика

`MailApiTokenTypeFactory.tornado()` возвращает `ru.mail.oauth2.access`.

`MailSessionSetterFactory.tornado()` создаёт `TornadoSession`.

`TornadoSession.urlSetup()` в стандартном случае добавляет:

`access_token=<ru.mail.oauth2.access>`

Отдельные команды могут переопределять транспорт этого же значения. Подтверждено: `MessagesSearchCommandNew` передаёт его как `t=<token>`, а `CallsBaseGetRequest` через `Authorization: Bearer <token>`.

`ServerCommandBase.getApiType()` переключает OAuth-совместимые команды на `TORNADO`, даже когда их исходный тип — `TORNADO_MPOP`.

Следовательно, `TORNADO_MPOP` нельзя исключать по названию: при включённом OAuth эти команды работают через наш `access_token`.

## Исправление прежнего решения

Прежнее правило «только aj-https.mail.ru» отменено.

В частности, новый поиск:

`https://go.mail.ru/api/v1/go/search/emails`

снова входит в исследование, поскольку `MessagesSearchCommandNew` имеет OAuth-совместимый тип `TORNADO_MPOP`, а значит при OAuth использует `TORNADO` и `ru.mail.oauth2.access`.

Все последующие карты API должны классифицировать операции по типу авторизации, а домен хранить как отдельное свойство маршрута.

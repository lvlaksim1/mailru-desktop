# MailRu Desktop v0.3.45: независимая регистрация Google, группы PushMe и соединение MCS

## Основание и гарантированная база

Владелец на v0.3.43 подтвердил одиночную подписку: `ACCOUNT_ACCEPTED` + фактический `MAILRU_NEW_MAIL_EVENT_RECEIVED=YES`. На v0.3.44 подтвердил один общий Google-получатель для 19 аккаунтов: `SERVER_API_CODE=0`, `PUSHME_ACCEPTED=19`, затем `NEW_MAIL_EVENT` и появление уведомления Windows. При 32 ранее было `499 / INVALID_FORMAT`. Предел групп и способность последовательных запросов сохранять ВСЕ предыдущие группы не доказаны.

## Этапы

1. **Google**, только по явной команде «Зарегистрировать Google»: `EnsureGoogleRecipientAsync` считывает защищённый `google-push-receiver.dat`; если там уже есть удостоверенный получатель, **не вызывает Google Checkin/register3**. Если отсутствует, создаёт одного нового получателя, сохраняет идентификатор `device_id`, `security_token` и `registration_token` через DPAPI. Также сохраняется независимый PushMe CommonId. Данные никогда не показываются в UI и не печатаются в диагностике. При потере связи новая регистрация Google не выполняется.
2. **PushMe**, явная команда «Зарегистрировать выбранные»: пользователь отмечает произвольное число свободных почтовых аккаунтов. Один POST `/api/v2/set_settings` содержит только отмеченные аккаунты и существующий `registration_token`. Никакого нового Checkin, Google register3 и MCS на этом этапе. После успешного ответа сохраняется группа с составом подтверждённых аккаунтов и временем; ответ с ненулевым `error.code` не создаёт группу. Один аккаунт может принадлежать только одной группе. Данные реестра групп DPAPI (`push-groups.dat`). Регистрация одной группы не отправляет запросы отписки остальных групп.
3. **Google MCS**, независимый защищённый поток TCP/TLS: «Подключить MCS» запускает цикл чтения по списку уже подтверждённых аккаунтов, без POST в PushMe. Соединение автоматически возобновляется после разрыва с тем же `device_id/security_token`. Статус в настройках и окне управления: остановлен, подключается, подключён, переподключается, ошибка соединения. Режим приёма (вкл/выкл) сохранён отдельно от состава групп и восстановится после перезапуска.

## Семантика кнопок

- **«Остановить приём»**: `MailRuPushBackgroundService.StopListeningOnly()` отменяет только чтение MCS. Никаких `unsubscribe_by_device_id` или `unsubscribe_by_token` и никакого удаления локальных Google/PushMe данных. Закрытие окна управления также ничего не отключает.
- **«Удалить выбранную группу»**: после дополнительного подтверждения снимает каждую подписку только этой группы через `/api/v1/unsubscribe_by_device_id`; удаляет из локальной группы только подтверждённые сервером адреса. Не снимает Google-токен, незатронутые группы остаются. Поскольку запросы выполняются с интервалом не меньше 5 секунд, большой пакет удаляется не мгновенно. При сбое сетевого снятия аккаунт остаётся в группе.
- **«Удалить регистрацию Google»**: отдельное подтверждение, операция допускается **только после удаления всех групп и адресных подписок**. Применяется исходный вызов отзыва токена PushMe, и защищённое хранилище удаляется только при подтверждении.
- **Одиночная проверка**: отдельная, уже успешно проверенная функциональность со своим временным получателем. Пока постоянный MCS активен, сначала необходимо остановить общий приём; иначе окно выдаёт объяснение.

## Переход с v0.3.44

При первом чтении нового реестра сохранённый старый перечень подтверждённых подписок из `SharedGooglePushIdentityStore.SubscribedAccounts` может быть импортирован как **«восстановленная группа»**, без новых запросов к Google/PushMe и без предположения о новой регистрации на сервере. Технически API PushMe не имеет серверных объектов «группа» — это локальная единица управления. Импорт делается только один раз, чтобы не выдавать неизвестные результаты сетевых попыток за подтверждённые группы.

После добавления второй группы прежние группы отмечаются **«доставка после другой группы не проверена»**, потому что ещё нужно подтвердить, что PushMe не заменяет ранее зарегистрированный набор. При реальном получении нового письма для одного из аккаунтов группы ставится пометка **«событие нового письма получено»**; это доказывает доставку для одного адреса, не автоматически для каждого в группе.

## Безопасность и ограничения

- Все проверки в CI автономные, без Google/PushMe соединений; подлинное подтверждение совместного обслуживания нескольких групп требует реального пользовательского теста.
- Не отправлять клиентские OAuth, Google-токены, сырые ответы сервера или личные адреса аккаунтов в GitHub.
- `StopListeningOnly` принципиально отличается от старого `Reconcile(enabled:false)`, который отзывал весь Google-токен. Новый управляющий интерфейс использует **только** первый.
- Подтверждение сервера о регистрации группы не равно подтверждению длительной доставки по каждому её аккаунту. При таймауте POST с неопределённым результатом старый реестр учётных записей сохраняется ради безопасного последующего анализа; бесконтрольное повторение запросов не допускается.

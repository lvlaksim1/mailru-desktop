# MailRu Desktop: встроенное испытание событий новых писем

Дата: 09.10.2026. Версия для проверки: **v0.3.33**.

## Назначение

Встроить прежнюю отдельную проверку мобильного механизма уведомлений в **основное приложение** на .NET 8, без Python, стороннего `.exe`, командной строки, дополнительного WebView2 или периодического опроса папки.

В «Настройках» — раздел «Уведомления о новых письмах (испытание)» и кнопка «Проверить получение новых писем». Открывается нативное окно с выбором любого уже авторизованного аккаунта, явным согласием на временную подписку, кнопками «Начать проверку» и «Остановить» и хронологией технических состояний. Автоматически при запуске программы механизм **не включён**.

## Архитектура

- `src/MailRuDesktop.App/MailRuPushProbe.cs` — собственный транспорт Google Check-in, регистрация для отправителя `1098335887158`, TLS/MCS `mtalk.google.com:5228`, подписка `alt-push-me.mail.ru/api/v2/set_settings` с точной схемой исходного `MailCapabilitiesProvider`, ожидание события `event=4`, снятие *собственного временного* токена через `/api/v2/unsubscribe_by_token`.
- `src/MailRuDesktop.App/PushProbeWindow.cs` — окно, вход только по сохранённому мобильному OAuth `AuthorizationStore.TryRestore`; токен не выводится, не записывается в отчёт и не посылается в сторонний сервис.
- `src/MailRuDesktop.App/MainWindow.PushProbe.cs` — подключение из основного окна; одно обновление списка выбранного аккаунта после подтверждённого `event=4`, **не опрос по таймеру**.
- `src/MailRuDesktop.Protocol/MailRuProtocol.cs` — два адреса PushMe зафиксированы в проверяемом каталоге разрешённых адресов с уровнем доказательности `StaticOfficialClient` (не `VerifiedLocal`).
- `tests/InteractionLogicSmoke`, `tests/WindowsUiSmoke` — проверка кодирования, структуры подписки, отказа без `validate_result`, принадлежности сообщения пакету `ru.mail.mailapp`, открытия окна и невозможности запуска без согласия.

## Последовательность испытания

1. Открыть MailRu Desktop, раздел **Настройки → Уведомления о новых письмах (испытание)**.
2. Нажать **Проверить получение новых писем**.
3. Выбрать подключённый аккаунт, желательно специальный испытательный ящик. Установить галочку согласия и нажать **Начать проверку**.
4. После успешного этапа `ACCOUNT_ACCEPTED` отправить на этот ящик контрольное письмо с другого устройства; в течение трёх минут следить за сообщениями состояния.
5. В случае получения `MAILRU_NEW_MAIL_EVENT_RECEIVED=YES` основной список обновляется событием. В любом исходе программа пытается снять *только* собственный временный токен, не затрагивая телефон.

Техническая последовательность подтверждена прежними одноразовыми опытами с Google (TOKEN_ISSUED, MCS LOGIN_OK), однако в составе MailRu Desktop **не выполнялся живой опыт с конкретным почтовым аккаунтом и событием нового письма**. Не путать успешную сборку/автономные тесты с подтверждением серверной подписки.

## Безопасность и известные ограничения

- Токен существующего телефона не читается и не используется. Windows создаёт самостоятельный получатель; испытательная подписка очищается по токену конкретного опыта.
- Почтовая авторизация доступна только из защищённого хранилища и только после явного запуска пользователем. Пароли, Google-токены и содержимое писем не передаются в GitHub.
- Свойства аппаратной платформы Android в пробном запросе **синтетические** (помечены в исходнике), поскольку компьютер физически не является Android-телефоном.
- Поддерживается одна отдельная подписка выбранного аккаунта на три минуты. Постоянное получение событий, восстановление длительных разрывов связи, многопользовательский режим и подавление повторных уведомлений — предмет дальнейшего этапа после подтверждения фактического `event=4`.
- Пограничные состояния (принятие регистрационного токена Google, TLS-логин, ответ PushMe, реальное событие, состояние удаления) представлены раздельно. Сообщение `LOGIN_OK` не считается доказательством доставки письма.
- Нет отдельной службы, второй копии WebView2, опроса папок по таймеру и новой установки по компьютеру.
- Автоматический выпуск через существующую схему: полный установщик и обновление в последнем выпуске GitHub.

## Статус

Реализовано в исходном коде. Проверка сборки и установки обязательна до предоставления нового релиза. Реальную доставку письма подтвердит только локальный опыт пользователя.

# Диагностика постоянного Google / PushMe соединения в MailRu Desktop

Дата: 09.10.2026. Назначение: определить причину наблюдаемого цикла `LOGIN_OK → 0 из 32 → соединение прервано → 45 / 90 сек повтор`. **Наличие LOGIN_OK ещё не доказывает успешную подписку PushMe.** Диагностика не изменяет протокол, интервалы запросов, Google-токены или подписки и не создаёт сетевые опыты.

## Где смотреть

Настройки → «Диагностика Google и PushMe». Журнал обновляется при каждом событии и сохраняется между запусками в
`%LOCALAPPDATA%\MailRuDesktop\push-diagnostics.log`.
Максимальный размер файла 256 КиБ; при переполнении сохраняются последние 900 строк.
В интерфейсе отображаются последние 140 строк. Кнопки: «Обновить журнал», «Копировать отчёт», «Сохранить в TXT», «Очистить журнал». Копирование и сохранение включают последние 900 строк.

## Порядок этапов и значения

- `[FLOW] IDENTITY_LOAD / IDENTITY_REUSED / IDENTITY_CREATE / IDENTITY_CREATED` — чтение сохранённой регистрации или новая регистрация Google.
- `[FLOW] MCS_TCP_CONNECT / MCS_TCP_CONNECTED` — установка TCP к mtalk.google.com:5228.
- `[FLOW] MCS_TLS_HANDSHAKE / MCS_TLS_OK` — TLS.
- `[FLOW] MCS_LOGIN_SEND`, `[MCS] LOGIN_VERSION / LOGIN_TAG`, `[FLOW] MCS_LOGIN_OK` — вход в MCS и технический тип ответа.
- `[FLOW] PUSHME_BUILD_REQUEST / PUSHME_HTTP_SEND` — подготовка/передача подписок для нескольких аккаунтов.
- `[PUSHME] HTTP_STATUS` — числовой код HTTP; `SERVER_API_CODE` — код ошибки протокола PushMe; `[FLOW] PUSHME_ACCEPTED` и `[PUSHME] REJECTED_COUNT` — количество принятых/отклонённых подписок.
- `[FLOW] MCS_RECEIVE_STARTED` — после ответа PushMe началось чтение MCS.
- `[MCS] KEEPALIVE_SENT / PING_FROM_SERVER / OTHER_FRAME_TAG / NEW_MAIL_EVENT` — технические события потока без тела сообщения.
- `[FLOW] MCS_SERVER_CLOSE / MCS_KEEPALIVE_TIMEOUT` — способ завершения сеанса.
- `[ERROR]` — этап и безопасная категория исключения, например `MCS_RECEIVE_STARTED_MCS_END_OF_STREAM`, `PUSHME_HTTP_SEND_HTTP_CONNECTIONERROR` или `PUSHME_RESPONSE_REJECTED_PROTOCOL_STATE_FAILURE`. Не сохраняется `Exception.Message` или `ToString()`.
- `[WORKER] CONNECT_ATTEMPT / RETRY_DELAY_SECONDS / RECEIVER_STOPPED` — попытки повторного соединения и ожидание перед следующим запуском.

Если последняя строка сообщает только задержку, искать предшествующий ей `[ERROR]` и ближайший `[FLOW]`.

## Защита данных

Записываются **только ограниченные технические коды** `[A-Z][A-Z0-9_]{0,59}` и целочисленные значения: код HTTP, номер типа MCS, число аккаунтов, время задержки. Любые произвольные строки заменяются на `UNRECOGNIZED`. Не записываются имена аккаунтов, электронные адреса, токены OAuth/Google, device_id, заголовки/тела запросов, сырые ответы PushMe, содержимое писем и полные исключения. Отчёт хранится локально; автоматически никуда не отправляется. Отправка отчёта пользователем только по его решению.

## Приёмка

Автономные тесты проверяют запись кодов, классификацию потокового EOF и HTTP, отсутствие пользовательских/токенных строк, очистку файла. Windows WPF-тест проверяет отображение журнала и наличие органов управления. **Это испытание самой диагностики, а не реального исправления MCS.** Причина обрывов будет установлена после отчёта из обновлённого приложения.

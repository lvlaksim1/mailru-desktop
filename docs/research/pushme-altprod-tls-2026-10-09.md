# MailRu Desktop: неудачная первая подписка и проверка серверов PushMe

Дата: 09.10.2026. Исходная версия: **0.3.33**. Исправление подготовлено для **0.3.34**.

## Факты из испытания пользователя

Непосредственно внутри MailRu Desktop прошли: создание собственного получателя Google, выдача токена для отправителя Mail.ru и защищённый вход в Google MCS (`TOKEN_ISSUED`, `LOGIN_OK`). При `POST` подписки выбранного аккаунта на прежний адрес `alt-push-me.mail.ru/api/v2/set_settings` программа показала обобщённую ошибку сетевого соединения; после неё удаление временной подписки не подтверждено. Настоящее новое письмо не проверялось. Пароли/токены пользователя для анализа не нужны и не запрашивались.

## Проверка без пользовательских данных

Из исходного APK `ru.mail.mailapp` 15.107.0.148045 установлены два штатных класса настроек хоста:
- `PusherHost.AltProd` — `alt-push-me.mail.ru` (использовался v0.3.33);
- `PusherHost.Prod` — `push-me.mail.ru` (штатный альтернативный сервер в исходном APK).

[Испытание №37881120525](https://github.com/lvlaksim1/mailru-desktop/actions/runs/37881120525) из внешней Linux-сети:
- `alt-push-me.mail.ru`: DNS разрешается, проверка цепочки сертификатов TLS заканчивается `SSLCertVerificationError`;
- `push-me.mail.ru`: DNS и TLS успешно (TLS 1.2);
- `aj-https.mail.ru`: DNS и TLS успешно.

[Испытание №37881273739](https://github.com/lvlaksim1/mailru-desktop/actions/runs/37881273739):
- `alt-push-me.mail.ru`: `TLS=INVALID`, `verify_code=20`, `unable to get local issuer certificate`;
- `push-me.mail.ru`: POST `/api/v2/set_settings` с пустым JSON-массивом `[]` (без токена/аккаунта) получает HTTP 200, проверка сертификата успешна. Это показывает работоспособность пути HTTP, **но не подтверждает успешную подписку реального аккаунта**.

Важно: испытания сделаны из GitHub, не из локальной сети владельца, и **не доказывают** точную причину TLS-ошибки на его компьютере. Тем не менее повторение одного и того же отказа на подписке и очистке именно `AltProd` делает адрес существенным подозреваемым.

## Исправление

В `MailRuPushProbe.cs` заменён адрес вызовов подписки и снятия временного токена на **штатный `PusherHost.Prod`**: `https://push-me.mail.ru/api/v2/set_settings` и `https://push-me.mail.ru/api/v2/unsubscribe_by_token`. **Проверка TLS-сертификатов не отключена**. Клиент по-прежнему выступает как мобильное приложение и использует официальный сетевой формат `application=mail`, `platform=android`, `can_mail`.

Ошибки сетевого соединения теперь разделяются на DNS, проверку сертификата TLS, установление соединения, повреждённый HTTP-ответ и преждевременное завершение ответа. Код HTTP-отказа выводится отдельно. Текст исключения, который может содержать адреса или секреты, не выводится. Ожидание ответа без явной команды остановки не должно ошибочно обозначаться как «Проверка остановлена».

Дальнейший критерий: запустить новую версию приложения на том же сохранённом тестовом аккаунте и посмотреть на `Mail.ru: ...` и `ACCOUNT_ACCEPTED`. Только реальное `event=4` подтверждает работоспособность уведомлений; ответ пустого POST и отдельный Google `LOGIN_OK` недостаточны.

Не создавать отдельную тестовую программу и не отправлять почтовые токены в GitHub.

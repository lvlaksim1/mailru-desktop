# Результат диагностики PushMe: HTTP 200, код протокола 499

Дата: 09.10.2026. Источник: обезличенный журнал владельца от 18:30–18:33 МСК из установленной v0.3.39. Запросы к серверам для исследования **не выполнялись**.

## Установлено фактически

- 18:31:56 — первая попытка подключения 32 сохранённых аккаунтов.
- 18:32:03 — Google Identity создана.
- 18:32:07 — Google MCS TCP/TLS и LOGIN_OK, версия=41, тип ответа=3.
- 18:32:12 — PushMe POST set_settings, HTTP 200, **application error.code=499**.
- 18:32:12 — Windows сама завершила открытый MCS канал из-за исключения `PUSHME_RESPONSE_REJECTED`, назначила повтор через 45 секунд.
- 18:32:57 — повтор с **той же** сохранённой Google Identity, новый MCS LOGIN_OK.
- 18:33:02 — снова HTTP 200 и `error.code=499`; повтор через 90 секунд.

Следовательно: нет доказательств отказа Google MCS, сетевого TCP/TLS или самостоятельного закрытия канала Google. Регистрацию **всего набора** аккаунтов отклоняет сервер PushMe; клиент прекращает MCS-сеанс по своей текущей обработке ошибки.

## Первичные исходники оригинального APK

Original `com.vk.pushme.network.PushMeApiImpl.parseSubscriptionResponseToResult`: при `response.error.code != 0` формирует `SubscriptionResult.ServerError(code, message)`, а не ошибку TCP или Google. `SubscriptionResponse.Error` имеет **message**, которое в Windows v0.3.39 ранее не анализировалось.

Original `SubscriptionUseCase.PUSH_ME_BATCH_LIMIT = 20` и `SubscriptionBatcher.batch`: группирует запросы по `application`; группы конкретного приложения добавляет целиком. **Нельзя** автоматически заключить, что одно приложение с 32 аккаунтами следует разбивать по 20 или что именно этот лимит вызвал 499. Нужно подтвердить серверную причину из error.message.

Original `DeviceIdProviderImpl.getDeviceId()` возвращает `getSdkDeviceId()`; оба значения SDK являются одним идентификатором CommonIdProvider. Нельзя объявлять равенство `device_id` и `sdk_device_id` ошибкой только потому, что методов два.

`499` здесь — **не HTTP 499 nginx**, поскольку сетевой ответ HTTP 200, а 499 — числовое поле в JSON PushMe. Расшифровки 499 по фиксированной таблице в изученном APK не установлено.

## Изменения v0.3.40

- `PushDiagnostics.SafeServerReason` извлекает из `error.message` только слова из небольшого разрешённого словаря. Сначала удаляет адреса почты, URL и длинные непрозрачные значения. Ни исходное сообщение, ни секреты в журнал не пишутся.
- Исходный `PushMeApiImpl` читает и `code`, и `message`. Windows теперь сохраняет лишь обезличенную категорию `[PUSHME] SERVER_REASON_...` и код.
- Интерфейс явно сообщает `PushMe отклонил регистрацию`, а не `Соединение прервано`; в отчёте сохраняется цепочка обоих событий. Код Google/PushMe запросов и параметры не изменены, никаких проверочных запросов не выполнялось.

## Оставшийся вопрос

Необходимо увидеть обезличенную категорию `SERVER_REASON` из **одного обычного** запроса приложения после установки v0.3.40. Если появится `UNCLASSIFIED`, первоначальное серверное сообщение остаётся недоступным; нельзя заменять источник догадками. Исправлять конкретный запрос только при подтверждённом протокольном расхождении с оригинальным APK либо установленном ответе сервера. Отдельная архитектурная проблема: текущий Windows-клиент сбрасывает работающий Google MCS при ошибке PushMe, а оригинальный APK полагается на независимый Google Play services; её надо устранять после формальной проверки без подмены сервера попытками.

Версия v0.3.40 не является подтверждением успешной подписки 32 аккаунтов.

# Адресное снятие подписки: восстановлено по байткоду оригинального APK

Дата: 09.10.2026.
Изначальная проблема: MailRu Desktop v0.3.37 удалял один аккаунт через общий `unsubscribe_by_token`, после чего выпускал новый Google-токен и повторно подключал остальных. Это не соответствует поведению актуального PushMe SDK.

## Первоисточник и степень доказательности

Исходный комплект `ru.mail.mailapp` версии `15.107.0.148045`, восстановлен из частей исследовательской ветки и проверен по SHA-256 ZIP:
`42c976a0c2f3d5fb186a88bc855f782c81c8ce35f952fcf22f99c64828880af6`.

Статическая трассировка Dalvik (без единого запроса к Google/Mail.ru):
[original-apk-pushme-unsubscribe-dex-2026-10-09.md](original-apk-pushme-unsubscribe-dex-2026-10-09.md).

Оригинальные вызовы:
1. `ru.mail.util.push.pusher.PushMeSDKPusherTransport.unsubscribeAppByDeviceId` → `PushMeSdk.getApp(application).unregisterAccount(account).execute()`.
2. `com.vk.pushme.logic.request.UnsubscribeRequest.execute`: выбор конкретных подписок из локальной БД, затем `UnsubscribeUseCase.invoke`; локальные записи удаляются **после** `Result.OK`.
3. `com.vk.pushme.logic.usecase.UnsubscribeUseCase.invoke`: `DeviceIdProvider.getDeviceId()`; имя аккаунта и приложения приводятся к `Locale.ROOT` в нижнем регистре; по каждому выбранному аккаунту вызывается `PushMeApi.unsubscribeByDeviceId(account,deviceId,application,...)`.
4. `com.vk.pushme.network.PushMeApiImpl.unsubscribeByDeviceId`, DEX `classes19.dex`:
   - HTTP **POST**
   - путь **`/api/v1/unsubscribe_by_device_id`** (именно V1 для удаления, при том что регистрация выполняется через V2);
   - тип тела **`application/x-www-form-urlencoded`**;
   - поля **`account`**, **`device_id`**, **`application`**;
   - результат успеха только при `response.error.code == 0`.
5. `PushMeApiImpl.unsubscribeByToken` использует **другой** путь `/api/v2/unsubscribe_by_token` и удаляет по общему Google-токену, не соответствует событию удаления одного аккаунта.

**Идентификаторы:** `device_id` — это `DeviceIdProvider.getDeviceId()`, соответствующий идентификатору `settings.device_id` при регистрации. Это НЕ `token` Google и НЕ отдельное `sdk_device_id`. Windows сохраняет свой постоянный device_id как `mailru-windows-` + hex ID существующей Google-регистрации и использует то же значение в обеих операциях.

## Исправленная Windows-логика

- Удаление одного аккаунта из 32: локальный список разрешённых аккаунтов сразу исключает его из маршрутизации новых писем; **Google-токен и действующее MCS-соединение не меняются**. Отправляется только описанный выше адресный запрос снятия подписки удалённого аккаунта.
- `SharedGooglePushIdentityStore` сохраняет набор потенциально действующих почтовых подписок. При успехе запроса удаляется лишь один адрес; при ошибке/недоступности сервера он остаётся для повторной попытки. Защита — DPAPI Windows.
- После реального разрыва/переподключения общий получатель заново регистрирует **актуальный**, а не устаревший список авторизованных аккаунтов, и сначала пытается снять отложенные адресные подписки. Удалённый аккаунт не может получить событие в UI даже до ответа сервера.
- Удаление последнего ящика выполняет адресное снятие подписки с сохранением Google-получателя. **Явное выключение всего приёма уведомлений** остаётся отдельной операцией.
- Все сетевые изменения состояния подписок в одном экземпляре программы последовательно согласованы: регистрация всего списка и адресные отписки не могут изменить защищённое хранилище одновременно.

## Проверки и ограничения

Новые автономные проверки используют вымышленные имена и маркеры доступа и **не отправляют запросов** к реальным серверам. Проверяются URL V1, все три поля, нормализация имён, выбор только удалённого аккаунта, выбор алгоритма без переподключения, запрет обработки уведомлений от удалённых ящиков.

Остальная системная часть Google MCS (Google Play services/Firebase) не содержится в исходном APK Mail.ru и не объявляется буквально скопированной. Наличие в CI успешной сборки и автономных тестов не доказывает доставку на 32 действительных ящика: это отдельный пользовательский критерий приёмки.

Никакого изменения подписок мобильного телефона.

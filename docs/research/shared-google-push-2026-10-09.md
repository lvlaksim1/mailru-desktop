# MailRu Desktop v0.3.36 — один Google-получатель на все почтовые аккаунты

Дата: 09.10.2026. Решение владельца: перейти от одного получателя на каждый
аккаунт к одному постоянному получателю на установку Windows.

## Архитектура

- `MailRuPushBackgroundService`: ровно один последовательно перезапускаемый
  цикл MCS, один набор учётных записей с действительными локальными OAuth.
  Изменения списка и авторизации не запускают параллельных сеансов.
- `MailRuPushProbe.Shared.cs`: одна действующая Google-регистрация для
  отправителя `1098335887158`, один TLS-сеанс на `mtalk.google.com:5228`,
  один запрос PushMe V2 с массивом настроек всех почтовых аккаунтов.
- Для каждого аккаунта сервер должен вернуть `validate_result.account` и
  `is_valid=true`. Событие нового письма обязательно должно содержать
  `category=ru.mail.mailapp`, `event=4` и действующий `account`.
  Сообщения с отсутствующим или чужим аккаунтом не вызывают обновление почты.
- Устранение повторов по идентификатору сообщения MCS и имени почтового ящика.
  Подтверждения MCS и контроль доступности общего канала сохранены;
  разрыв приводит к ограниченной по частоте повторной попытке.

## Сохранение и снятие подписок

- Один Google device ID, security token, registration token и список потенциально
  зарегистрированных аккаунтов сохраняются в
  `%LOCALAPPDATA%\MailRuDesktop\google-push-receiver.dat`.
  **Весь файл защищён DPAPI текущего пользователя Windows**.
- Нормальный выход и запуск программы не удаляют Google-токен и не создают
  новую Google-регистрацию.
- Добавление аккаунта или обновление его OAuth: тот же общий токен, новая
  серверная регистрация всего требуемого набора.
- Удаление одного аккаунта: серверный метод
  `unsubscribe_by_token` является **общим** для всех подписок. Поэтому
  последовательность специально требует успешного снятия старого общего
  токена, удаления старой локальной идентичности, выпуска нового Google-токена
  и повторной подписки **всех оставшихся аккаунтов**. Это консервативный
  способ исключить подписку удалённого ящика, пока безопасная адресная операция
  удаления одного аккаунта не подтверждена протоколом.
- При ошибке снятия общего токена сохранённая идентичность не удаляется:
  новые регистрации блокируются до успешной повторной попытки. Не объявлять
  удаление подтверждённым по одному HTTP 200.
- При выключении уведомлений общий токен снимается после завершения
  сеанса. Если сеть недоступна, локальное зашифрованное состояние сохраняется
  для следующей попытки.
- Ручная трёхминутная диагностика по выбранному аккаунту остаётся отдельным
  явно запускаемым временным опытом и не выполняется параллельно с фоновым
  каналом.

## Доказательность

- Код и автономные проверки подготовлены без реальных OAuth/токенов Google.
- Предыдущий живой опыт пользователя v0.3.35 подтверждает доставку
  **одному** аккаунту через PushMe / Google MCS.
- Новый **общий** канал и одновременная подписка нескольких настоящих
  аккаунтов должны быть подтверждены в установленной v0.3.36 отдельно.
- Не путать успешную сборку и автономные проверки с проверенной длительной
  доставкой после переподключения, удаления и повторного добавления аккаунтов.
- Не использовать периодический опрос почты; не изменять телефонные подписки.

# v0.3.44 — сравнительная проверка одного и 19 аккаунтов

## Основание
Владелец повторно подтвердил на v0.3.43 успех одиночной проверки (19:58:24 ACCOUNT_ACCEPTED, 19:59:18 MAILRU_NEW_MAIL_EVENT_RECEIVED=YES, 19:59:23 успешное снятие временной подписки). При предыдущей общей регистрации 32 почтовых ящиков PushMe возвращал HTTP 200 с JSON error.code=499 и сообщением INVALID_FORMAT. Google MCS успешно выполнял вход.

Ограничение веб-интерфейса Mail.ru на 20 аккаунтов **со слов владельца** — гипотеза, а не доказанный предел API PushMe. В оригинальном APK SubscriptionUseCase встречается число 20, но группировка SubscriptionBatcher выполняется по application, поэтому из исходников ещё нельзя уверенно вывести лимит 19/20 почтовых ящиков в одном POST.

## Два режима — оба только по явному действию

1. **Один аккаунт**: существующая 3-минутная проверка без изменений, индивидуальный временный Google-токен, запрос PushMe из успешной v0.3.35, уведомление о письме, снятие временного токена при завершении.
2. **19 аккаунтов**: отдельное окно, список авторизованных аккаунтов, предварительно отмечены первые 19, пользователь вправе изменить выбор. Запуск возможен только при ровно 19 разных ящиках и отдельном подтверждении. Существующий общий получатель Google (либо создаваемый при отсутствии) и **один общий запрос** `/api/v2/set_settings` с ровно 19 объектами. Форма и значения полей общих объектов не меняются относительно предыдущей версии с 32: меняется только выбранный набор. Это контролируемая проверка именно количества, а не новой сериализации. Остальные сохранённые ящики не добавляются и не отписываются.

Автоматическая массовая подписка на старте остаётся полностью отключённой, невзирая на ранее сохранённую пользовательскую настройку. Прежняя настройка сохраняется для следующих выпусков. Одновременно запускать оба режима нельзя. При ручной остановке 19 аккаунтов соединение прекращается и ставится в очередь адресное снятие их подписок по оригинальному `unsubscribe_by_device_id`, **не отзывая общий Google-токен**. Из-за соблюдения ≥5 сек между сетевыми запросами снятие 19 подписок занимает заметное время. Подтверждение удаления следует смотреть в техническом журнале; при сетевой ошибке остаётся запись для последующей попытки. Новая версия не пытается автоматически повторять отклонённую групповую регистрацию через 45/90 секунд: одна проверка — один цикл, чтобы не нагружать сервер.

При получении `event=4` аккаунт определяется по содержимому события, поэтому уведомление через существующий `NotifyIcon.ShowBalloonTip` отображается только для выбранного аккаунта, который принял PushMe. Включение всплывающих уведомлений независимо от режима.

## Критерии пользовательской проверки

- Выбор только 19 аккаунтов и регистрация в одном запросе: [FLOW] PUSHME_HTTP_SEND count_or_code=19.
- Ответ приложения: [PUSHME] SERVER_API_CODE и SERVER_REASON (при отказе). Значение 0 и [FLOW] PUSHME_ACCEPTED count_or_code=19 означает принятие всех 19, но не доказывает получение писем без реального event.
- Если повторится 499 INVALID_FORMAT, гипотеза «только более 20 аккаунтов» не подтверждается; необходимо изучать форму общей регистрации по отношению к проверенному одному аккаунту, особенно идентификаторы, а не искать причину в лимите веб-интерфейса.
- При реальном новом письме должна появиться [MCS] NEW_MAIL_EVENT и (если отмечено) системное всплывающее уведомление.

Офлайн проверка Windows выполняется на фиктивных адресах, без сетевых проб, пользовательских секретов или изменений телефонных подписок.

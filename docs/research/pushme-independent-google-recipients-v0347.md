# MailRu Desktop v0.3.47 — независимые Google-получатели PushMe

## Основание и граница доказательств

Пользователь проверил регистрацию одной группы через официальный PushMe: 19, 21 и 30 аккаунтов приняты и сопровождались доставкой, а 31 и 32 отклонены. Для запроса из 32 получены HTTP 200, серверный JSON `error.code=499`, `INVALID_FORMAT`. Принятый локальный предел программы — 30 аккаунтов на пакет. Гарантий отсутствия иных серверных ограничений нет.

При последовательных регистрациях двух групп на одном Google-токене события второй группы шли, первой перестали. Точная семантика `set_settings` не установлена. Поэтому клиент больше не назначает один Google-получатель двум **новым** группам.

## Изоляция и сохранение данных

- Исходная Google-регистрация остаётся в файле `google-push-receiver.dat` без изменения пути и DPAPI-защиты.
- Для дополнительных Google-регистраций используется защищённый `google-push-receiver-<12 hex>.dat`. Каждый файл хранит собственные DeviceId, SecurityToken, FCM RegistrationToken, PushMe CommonId и адресный список подписок.
- Группа сохраняет `RecipientId`. Отсутствующее поле в прежнем реестре трактуется как `primary`; существующие группы и Google-токен **не пересоздаются**.
- Свободный получатель назначается **до** PushMe POST; каждое новое создание группы выбирает отдельного незанятого получателя. Если свободного нет — регистрация не выполняется до явного создания нового.
- Для каждого получателя создаётся отдельный Google MCS worker. Повторные подключения работают `listenOnly` и не вызывают новые `set_settings` POST.
- Остановка MCS не отзывает Google-токены или PushMe-подписки.
- Удаление группы адресно использует её сохранённый Google/PushMe CommonId. Другие получатели не трогаются. `NOT_TRACKED` теперь НЕ считается подтверждённой серверной отпиской.

## Интерфейс

- Список занятых/свободных Google-регистраций и ручная кнопка создания нового получателя.
- Группы содержат адресную привязку Google, лимит новой группы 30; прочие аккаунты не затрагиваются.
- Окно управления группами отображает фактическое число обработанных отписок и их результаты.

## Цикл обновления

Самостоятельная программа обновления показывает одно окно на протяжении скачивания и установки. После загрузки она передаёт локальную команду основному приложению корректно завершиться, ждёт выхода, запускает установщик Inno с `/VERYSILENT`, отображает процесс установки до его завершения, затем закрывает окно после автоматического запуска новой версии. Прежний рабочий стол и ярлыки остаются нетронутыми. Обновление **с предыдущей версии** первоначально запускает ещё прежний механизм — новая схема доступна после установки версии, содержащей UpdateAgent.

## Проверки и ограничения

Автономные проверки подтверждают отдельные DPAPI-слоты и независимые группы, Windows CI проверяет компиляцию, запуск и интерфейс. Реальная эксплуатация нескольких MCS-соединений должна быть проверена пользователем без экспериментальных регистраций со стороны разработчика; один факт CI не доказывает доставку всем аккаунтам.

# MailRu Desktop v0.3.35 — постоянное получение новых писем

Дата: 09.10.2026. Основание: реальное испытание пользователя в v0.3.34.

## Доказательство полного пути

В уже установленном MailRu Desktop, на подключённом к программе почтовом аккаунте пользователя, получены следующие технические состояния:

| Время на компьютере | Событие |
|---|---|
| 07:09:19 | Google: получатель зарегистрирован |
| 07:09:25 | `TOKEN_ISSUED` |
| 07:09:30 | `LOGIN_OK` |
| 07:09:35 | Mail.ru: `ACCOUNT_ACCEPTED` |
| 07:10:38 | **`MAILRU_NEW_MAIL_EVENT_RECEIVED=YES`** |
| 07:10:38 | Запрошено обновление списка |
| 07:10:43 | Временная подписка успешно снята |

Это подтверждает для испытанного ящика получение подлинного серверного события `event=4` без циклического опроса списка писем. Интервал 07:09:35–07:10:38 не является измеренной задержкой доставки, поскольку не указан момент отправки письма.

Сохранены проверенные параметры официального мобильного APK: `sender=1098335887158`, `app=ru.mail.mailapp`, `platform=android`, `application=mail`, HTTPS `https://push-me.mail.ru/api/v2/set_settings`, разрешения `can_mail`; транспорт `mtalk.google.com:5228` с проверкой TLS. Создаётся самостоятельный Google-получатель компьютера, существующий токен телефона не используется.

## Изменения v0.3.35

В действующее приложение встроен `MailRuPushBackgroundService`. При запуске MailRu Desktop и включённом переключателе в настройках он создаёт **отдельную подписку и соединение на каждый сохранённый авторизованный аккаунт**. Отдельные получатели позволяют однозначно сопоставить событие с аккаунтом, не меняя активный аккаунт пользователя.

- Получение нового письма вызывается **только серверным событием** `event=4`, а не проверкой списка почты по таймеру. Для активного аккаунта обновляется текущая папка и общие счётчики; для другого аккаунта обновляются счётчики без принудительного переключения.
- После разрыва защищённого соединения выполняется отдельное создание получателя и повторная подписка с нарастающими интервалами ожидания: от 45 секунд до 10 минут. При длительном успешном сеансе задержка перед следующим подключением сокращается.
- Поддерживается сердцебиение MCS при длительном отсутствии сообщений, ограничение времени ожидания ответа и выборочное подтверждение полученных сообщений с `persistent_id`. Обработка одинакового идентификатора события повторно подавляется ограниченным набором идентификаторов в оперативной памяти. Два разных письма подряд не должны ошибочно подавлять друг друга.
- Между началом внешних сетевых запросов Google/Mail.ru действует единое ограничение — минимум пять секунд даже при нескольких аккаунтах.
- При добавлении, удалении и обновлении авторизации аккаунта набор подписок согласуется с локальным хранилищем; пароль повторно не запрашивается. При закрытии приложения предпринимается завершение сеансов и снятие **только собственных** токенов, без вмешательства в уведомления телефона.
- Системное уведомление Windows из области уведомлений появляется при новом письме, включая случаи, когда окно приложения свёрнуто. Отправитель и содержимое письма не запрашиваются для системного уведомления; в нём указывается локально сохранённый адрес почтового аккаунта.
- В настройках доступен переключатель **«Получать новые письма автоматически, пока работает приложение»**. Он сохраняется в существующих настройках и позволяет выключить все автоматические соединения. Ранее созданное диагностическое окно остаётся доступным; при его открытии постоянные соединения останавливаются, чтобы не проводить двойные испытания.

Используется уже существующее хранилище авторизации Windows и существующий клиент WPF; новых экземпляров WebView2, установщиков дополнительных служб, независимых Python-программ, постоянных фоновых процессов после закрытия приложения и таймерного опроса почты нет.

## Что ещё требует проверки в реальной эксплуатации

1. Уже подтверждённая единичная доставка не доказывает, что новое постоянное соединение остаётся работоспособным **сутками**, после сна компьютера или смены сети; автоматические проверки охватывают поведение кода без личного почтового аккаунта.
2. Сервер Google и Mail.ru могут менять поведение, и повторная регистрация может не получиться. Не скрывать состояние «Ожидание повторного подключения» под видом успешной подписки.
3. Обработка повторных `persistent_id` проверяется в оперативной памяти; после полного перезапуска приложения получение повторного сообщения теоретически возможно, поэтому периодическую проверку доставки и расширение сохранения подтверждений следует исследовать отдельно.
4. В отличие от мобильного приложения Android, пока работает только в рамках процесса MailRu Desktop: закрытая программа не получает уведомления.
5. Опыт v0.3.34 доказал доставку на **один** авторизованный аккаунт. Параллельное использование нескольких ящиков, системные уведомления Windows, сон и восстановление соединений в v0.3.35 подлежат самостоятельному пользовательскому испытанию.

## Контроль выпуска

К выпуску допускается только программа, для которой прошли обязательная сборка Windows, автономные регрессионные тесты, проверка интерфейса WPF и проверка реестра элементов. Обычная схема GitHub Releases: полный установщик и файл обновления, прежние тяжёлые бинарные файлы не накапливать.

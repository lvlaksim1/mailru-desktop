# MailRu Desktop v0.3.64 — единая семантика локального и серверного поиска

Дата: 13.10.2026. Основание — пользовательский дефект после v0.3.63: по кнопке «Найти на сервере» показывается только часть результатов; после очистки строки становятся видимы все найденные письма. Пользователь одобрил предложенный план исправления и последовательной загрузки страниц.

## Причина

`MainWindow.ServerSearchButton_Click` вызывал `SearchMessagesAsync(..., limit: 200)`, записывал результат в `_currentMessages`, выставлял `_serverSearchMode=true` и сразу вызывал `ApplyFilters()`. Последний независимо от режима проверял в письмах только `Subject`, `Snippet`, `SenderDisplay`, `SenderEmail`. Совпадения, найденные сервером в **полном тексте**, отсутствовали в этих четырёх кратких полях и ошибочно скрывались. Очистка `FilterQueryTextBox` вызывала `ApplyFilters()` с пустой строкой и возвращала письма без повторного запроса.

## Изменение

1. В режиме обычного просмотра папки ввод текста по-прежнему локально фильтрует загруженный список.
2. После нажатия «Найти на сервере» результаты показываются целиком — никакой дополнительной фильтрации по тексту не происходит. Очистка и редактирование строки до нового серверного запроса не скрывают уже полученные письма. Кнопка «Сбросить» отменяет незавершённый поиск и заново загружает текущую папку.
3. `MailServerSearchPages` последовательно объединяет страницы исходного проверенного `aj-https.mail.ru/api/v1/messages/search` по `offset/limit` (лимит 200), удаляет повторы по ID, не смешивает счётчик сервера с количеством реально загруженных писем и прекращает загрузку на конце результатов, при пустой/полностью повторяющейся странице или по защитному ограничению в 100 страниц. Без явного `count` серверного ответа число результатов не выдумывается.
4. Между страницами выдерживается интервал не менее пяти секунд. Поиск асинхронный, интерфейс обновляет прогресс после каждой страницы. При недогрузке явно появляется отметка «результаты получены не полностью»; при сетевой ошибке после первых страниц сохранённый список не теряется.
5. Каждый поиск имеет поколение и токен отмены, привязанные к аккаунту, токену доступа и папке. При смене аккаунта, загрузке другой папки, сбросе или закрытии окна предыдущий поиск отменяется. Запоздавшие ответы не могут переписать список нового аккаунта.
6. В протоколе результат `MailRuSearchResult.HasReportedTotal` различает настоящее серверное поле `count` и резервный размер текущей страницы; существующие адреса и параметры API не изменены.

## Испытания

Автономные WPF-тесты: найденные сервером совпадения только в полном тексте остаются на экране, очистка строки не скрывает результаты, локальный поиск обычной папки действует как прежде, несколько страниц объединяются без повторов, смещение не зависит от удаления повторов, серверный счётчик показывается раздельно, повторяющиеся страницы безопасно прекращают загрузку, отсутствие `count` не превращается в вымышленную общую численность.

После публикации владелец проверяет в живой почте слово, встречающееся только в теле письма, очистку поля, сброс, поиск более 200 писем и смену аккаунта во время загрузки. CI не заменяет подтверждение реальной полноты ответов Mail.ru.

## Ограничение области изменений

Это функциональное исправление поиска, не этап 2 архитектурного рефакторинга. Центральный разделитель v0.3.63, действующая орфография, редакторы/вложения, аватары, HTML писем, авторизация, Google MCS/PushMe и почтовые операции не изменялись.

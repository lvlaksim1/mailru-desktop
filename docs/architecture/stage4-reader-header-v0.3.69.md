# MailRu Desktop — этап 4.1: самостоятельная панель заголовка письма

Дата 14.10.2026. Базовая версия 0.3.68; целевая 0.3.69.

Пользователь подтвердил исправность v0.3.68: основная подпись, расположение выбора шаблона/подписи, реальная очистка форматирования. Разрешён следующий шаг структурной переработки.

## Граница изменения

Вынесена панель сведений о выбранном письме (тема, имя отправителя, адрес отправителя и получателей, дата, служебные отметки) из MainWindow.xaml в автономный WPF-компонент MailReaderHeader.xaml + code-behind. Обработчик двойного щелчка по адресу передаёт событие существующему обработчику главного окна. Свойства MainWindow.ReaderHeaderAccess.cs сохраняют прежнюю точку обращения из логики просмотра/переписок. Никаких новых маршрутов, запросов, сохранённого состояния или действий пользователя не добавлено.

Критически: MessageWebView остаётся ровно там же, где был — один экземпляр, постоянный shell/DOM, без переносов между родителями и без нового перекрытия WPF. GridSplitter и его код не меняются. Сценарии «полное письмо → переписка → смена папки/аккаунта» остаются прежними.

## Проверки

- В CI проверяются сборка, автономные испытания, WPF испытания, проверка запуска, реестр элементов и почтовые адреса.
- Новые испытания: компонент занимает прежнюю строку Grid, адреса остаются только для чтения, имена и видимость полей сохранены, WebView2 по-прежнему только в основной панели, не внутри компонента.
- Пользовательская проверка: отсутствие мерцания, плавность разделителя, тема, двойной щелчок по адресам, переписки, вложения, ответ, переключение папки/аккаунта. Без пользовательского подтверждения визуальная эквивалентность не доказана.

Этап 4 остаётся частично выполненным: следующие самостоятельные компоненты просмотра и вкладок переносить только после приёмки этапа 4.1. Не объединять это с WebView2/протоколом/уведомлениями.

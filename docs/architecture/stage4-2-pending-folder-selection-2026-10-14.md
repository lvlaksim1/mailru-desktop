# MailRu Desktop — этап 4.2: сохранять последнее намерение выбора папки

Дата: 14.10.2026. Основа: v0.3.69, поколение 90.
Статус: изменения прошли Windows CI и пользовательскую приёмку указанных ниже сценариев. Перед объединением требуется итоговая CI.

## Доказанная по исходникам проблема

В предыдущей версии обработчик `FolderListBox_SelectionChanged` прекращал
выполнение при `_loadingFolder == true`; `LoadFolderAsync` тоже возвращался.
Выбор другой папки во время незавершённой загрузки мог быть безвозвратно
отброшен, хотя пользователь видел новое выделение. Реальный пользовательский
сбой не зафиксирован: это обнаруженный анализом кода дефект последовательности.

## Ограниченное изменение

1. Выбор мышью, клавиатурой и обычный обработчик изменения выделения обращаются
   к `RequestFolderSelectionAsync`.
2. Пока папка загружается, `PendingFolderSelection` хранит только последнюю
   явно выбранную папку и её исходный аккаунт/поколение переключения.
3. Если пользователь выбрал другую папку, старый ответ не публикуется.
   После завершения прежней загрузки выполняется последнее актуальное намерение.
4. Заявка старого поколения аккаунта не применяется после переключения аккаунта.
5. Загрузка, разбор ответов, команды над письмами и сетевой транспорт
   сохранены; новых запросов, кроме исполнения ранее потерянного выбора, нет.
6. WebView2, его постоянный документ и алгоритм отображения, разделитель,
   токены, настройки, обновление приложения и MCS/PushMe не изменены.

## Испытания

`InteractionLogicSmoke`: три последовательных выбора, возврат к уже
загружаемой папке, одноразовая обработка, сохранение заявки нового поколения,
отбрасывание устаревшей заявки предыдущего аккаунта.

`WindowsUiSmoke`: настоящие события выбора WPF при искусственно установленном
признаке загрузки, без сетевых запросов; последняя выбранная папка не теряется,
ранее подтверждённый идентификатор папки самовольно не изменяется.

Требуется успешная полная Windows CI и проверка на компьютере владельца:
быстрое переключение А → Б → В, повторный выбор А, смена аккаунта во время
загрузки, медленный/ошибочный сервер, открытие из уведомления, состояния
прочтения, группировка и пересчёт счётчиков. Отдельно проверить отсутствие
мерцания и эталонную плавность разделителя. Сборка не заменяет приёмку.

Ранее открытые вопросы (#77 «Отправить сейчас», серверный поиск >200, причина
временного отказа токенов) остаются самостоятельными. Этап 4.1 также ожидает
задокументированной визуальной приёмки.

## Пользовательская приёмка 14.10.2026

Владелец подтвердил корректную работу испытательной v0.3.70 после проверки:
открытие переписки; быстрое последовательное переключение нескольких папок во время
загрузки; возврат к исходной папке; смена аккаунта; отсутствие мерцания писем;
сохранение эталонной плавности центрального разделителя. Формулировка владельца:
«всё работает корректно».

Также владелец отдельно подтвердил корректность официальной v0.3.69 (этап 4.1).
Успешные испытания не доказывают отдельную проверку сетевых отказов, которую
следует оставить дополнительным испытанием при удобной воспроизводимой ситуации.

План выпуска: установить `VersionPrefix=0.3.70`, удалить временный
`stage4-2-trial-update.yml`, выполнить CI, объединить PR и опубликовать
штатные установщики через существующую процедуру выпуска без изменения
WebView2, разделителя, авторизации и MCS/PushMe.

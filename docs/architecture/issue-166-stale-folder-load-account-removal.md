# Issue #166 — завершение загрузки удалённого активного аккаунта

Дата: 14.10.2026. Основа: принятая v0.3.70, контекст поколения 95.
Статус: минимальное исправление в отдельной ветке, **не** официальный выпуск.

## Исходная последовательность и риск

1. `LoadFolderAsync` начал чтение почтовой папки A.
2. Владелец подтвердил удаление локально сохранённого аккаунта A.
3. `RemoveSavedAccountAsync` удалил запись авторизации и асинхронно удаляет профиль.
4. Старый ответ возвращается до/после очистки интерфейса.

В прежней реализации обычный вызов `LoadFolderAsync(folderId)` не
передавал `accountSwitchGeneration`, поэтому `IsStaleAccountSwitch`
для него всегда был ложным. Удаление не увеличивало поколение переходов.
Это проверяемый по исходникам путь возможной публикации старого ответа,
не ранее зарегистрированный пользовательский сбой.

## Реализованное ограниченное изменение

- `FolderLoadIdentity` запоминает поколение и имя аккаунта, когда
  начинается загрузка. Токен намеренно не включён в условие актуальности:
  нормальное чтение папки может успешно обновить его внутри операции.
- После каждого значимого `await`, непосредственно перед публикацией
  результата и при обработке ошибки, загрузка проверяет неизменность
  обоих признаков. Это относится и к обычной загрузке без
  явного параметра поколения.
- Сразу после успешного удаления сохранённой записи **активного**
  аккаунта повышается поколение и отменяется действующий поиск.
  Удаление других аккаунтов не нарушает текущую загрузку.
- После асинхронного удаления профиля код ещё раз проверяет, что удалённый
  аккаунт остался активным перед очисткой. Если пользователь уже выбрал
  другой аккаунт, очищать его состояние запрещено.
- При переключении на следующий сохранённый аккаунт прежняя загрузка
  сначала должна освободить признак занятости; более поздний явный
  выбор аккаунта имеет приоритет.

WebView2, постоянная HTML-оболочка, центральный GridSplitter, внешний HTTP
клиент, маршруты Mail.ru, получение уведомлений, шифрование и структура
хранилища не менялись.

## Проверки

В `InteractionLogicSmoke`:
- неизменный аккаунт принимает свой результат;
- удаление во время искусственно задержанного ответа делает публикацию
  недопустимой, даже если имя и токен ещё не были очищены;
- поздний результат не может заполнить новый аккаунт;
- обновление токена в том же аккаунте не прерывает корректную загрузку;
- результат другого аккаунта не публикуется в текущем;
- поздняя ошибка подавляется той же проверкой актуальности.

В `WindowsUiSmoke`:
- на экземпляре MainWindow без сервера используются фиктивные токены и
  временно подставленное состояние;
- вызывается действующая проверка `IsCurrentFolderLoad`;
- проверяются разрешённая публикация и запрет после изменения поколения;
- исходное состояние окна восстанавливается.

Никакие тесты не вызывают реальное удаление аккаунта. Полная Windows CI
и пользовательская проверка — отдельные этапы, прежде чем объединять и
публиковать новую версию.

## Остаточные ограничения

Испытание непосредственно полной цепочки `RemoveSavedAccountAsync` с
реальным HTTP-ответом и диалогом не проводилось: оно требует контролируемого
внедрения транспорта. Приведённые испытания доказывают запрет публикации
по общему исполняемому условию, но не исчерпывают все возможные сочетания
параллельных команд и авторизации.

Исторические задачи #77, поиск >200 и прежняя проблема авторизации не
считаются устранёнными. Принятая пользователем официальная v0.3.70 в
`main` не изменена до отдельного решения о выпуске.

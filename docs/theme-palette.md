# Система цветовых ролей MailRu Desktop

## Правила

Цвета назначаются **элементам через фиксированные роли**, а не пользователем напрямую отдельным кнопкам или текстовым блокам. Каталог `ThemePalette.Roles` содержит 26 технических ключей ресурсов WPF ради совместимости со старыми настройками. Пользователь видит **20 общих настроек цветов** (`ThemePalette.EditableRoles`). Одинаковые по назначению элементы используют один редактируемый цвет.

Два независимых набора настраиваемых цветов хранятся в `settings.json` в `DarkPalette` и `LightPalette`. «Системная» тема автоматически выбирает один из этих наборов по настройкам Windows. Неверные шестнадцатеричные значения и посторонние ключи при чтении пропускаются. Изменение допустимой роли действует сразу, без перезапуска. Назначение элементов ролям пользователь изменить не может.

Стандартные значения исходят из спокойной нейтральной схемы с синим основным акцентом. Роли и контраст проверяются автоматическими испытаниями. При недостаточной контрастности редактор предупреждает, но **не подменяет** выбранные цвета.

## Что нельзя перекрашивать

- Аватарки, изображения вложений, логотипы отправителей.
- Изображения и собственное содержимое полученных HTML-писем. В тёмной теме возможны общие защитные переопределения фона/текста, но собственные фотографии должны оставаться неизменными.
- Фирменную иллюстрацию значка приложения.

## Пользовательская настройка

**Настройки → Внешний вид → Цвета элементов интерфейса**. Выберите «Тёмная» или «Светлая» и измените цвет роли в формате `#RRGGBB` либо через диалог выбора RGB. Рядом с каждой ролью указан неизменяемый перечень элементов. Стрелка «↺» возвращает исходный цвет одной роли. Отдельная кнопка возвращает стандартные цвета всей выбранной темы с подтверждением.

Изменение набора, который сейчас применён, сразу обновляет ресурсы WPF, системную заголовочную полосу и просмотр писем. Изменение неактивного набора применяется после переключения темы. Ввод неверного цвета не сохраняется.

## Дисциплина разработки

В новых окнах и элементах используется `{DynamicResource App...Brush}`, а в программном коде — ресурс из `ThemeManager`. Не добавлять локальные шестнадцатеричные значения для цветов интерфейса и новые пользовательские цветовые роли без пересмотра их общей настройки и автоматических проверок. Непрозрачность, прозрачность, пиксельная геометрия и изображения не являются самостоятельными ролями.

Для сочетаний текст/фон проверяются рекомендации по контрастности 4,5:1; для значимых графических контуров — 3:1. Проверки являются предупреждением, а не принудительным ограничением выбора пользователя.


## Объединение сходных цветов в v0.3.28

В реестре ресурсов остаются все 26 прежних ключей: существующие окна и сохранённые настройки не требуют ручной миграции. В редакторе показывается 20 общих настроек. Подчинённые ключи получают цвет главного ключа:

| Общая настройка | Ключи, использующие её значение |
|---|---|
| Фон окна, панелей и диалогов | `AppWindowBrush`, `AppPanelBrush`, `AppDialogBrush` |
| Фон кнопок и полей ввода | `AppControlBrush`, `AppInputBrush` |
| Дополнительный и неактивный текст | `AppMutedTextBrush`, `AppDisabledTextBrush` |
| Основной текст и текст выделения | `AppTextBrush`, `AppSelectionTextBrush` |
| Ползунки и стрелки прокрутки | `AppScrollThumbBrush`, `AppScrollArrowBrush` |

У каждого общего цвета остаются отдельные значения для тёмной и светлой темы. При первом запуске новой версии сохранённое значение главного ключа имеет преимущество; если оно не изменялось, используется ранее настроенный цвет подчинённого ключа. Исходные сведения не удаляются из файла настроек. Изображения отправителей не перекрашиваются; их размеры изменяются вместе с размером шрифта интерфейса.
